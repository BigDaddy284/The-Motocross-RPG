# Motocross RPG Toolkit: instructions

How to use the game's editors: the **Track Editor** and the **Map Editor**, with the Outfit Designer and Character Designer to come. The toolkit's front page is `tools/index.html`, published at `…/tools/` beside the game. Each editor also has a **Help** button with the same guidance in short. See `ADDING_ASSETS_AND_TRACKS.md` for the game's data files and `MAP_EDITOR_TILE_GUIDE.md` for the tile sets.

## The toolkit

The editors are kept apart from the game as the **Motocross RPG Toolkit**: its front page is `tools/index.html`, published at `…/tools/` beside the game (http://localhost:5173/tools/ with `npm run dev`). It lists the **Track Editor** and the **Map Editor**, each its own page with a **Toolkit** link back, and placeholder pages for the **Outfit Designer** and **Character Designer** to come. The editors work on the game's own data files, and the track editor's race view runs the game itself. The game's menus don't link to the toolkit, so it never shows on a phone. To add a tool, put its page in `tools/`, add a card to `tools/index.html`, and add its file to `TOOLKIT_PAGES` in `vite.config.ts` so the build publishes it.

### Opening the toolkit as a desktop app (Windows)

Double-click **`Toolkit.cmd`** in the repo's folder. It checks Node.js is installed (and offers the download page if not), runs `npm install` the first time, starts the dev server out of sight and opens the toolkit in Edge or Chrome's app mode: a plain window with no address bar or menus, so none of the editors' shortcuts are taken by the browser (Alt+E, for one, opens the browser's own menu in a normal tab). Closing the window stops the server. If a dev server is already running (`npm run dev` in a terminal), the window just opens on it; otherwise it starts one on the first free port from 5173 up. The script is `tools/toolkit.ps1`; the window's browser profile is kept in `.toolkit-browser/`, which git ignores.

## Editing maps

`tools/map-editor.html` edits the game's maps, the tiles they are painted with and the buildings that stand on them, each on its own tab: **Map**, **Tiles** and **Buildings**. Open it one of these ways:

- With `npm run dev`, open http://localhost:5173/tools/map-editor.html and click **Load the game maps from this server**. **Save writes straight into the game**: maps, new tiles, building pictures and the building library. This is the easiest way.
- Or click **Open folder…** (Chrome or Edge) and pick the repo's `public` folder for the game maps, their tiles and the building library (`public/assets` works for maps and tiles but not buildings), or the shared `art` folder for the **Tiled source maps** (`.tmj`). Save writes back into the folder; other browsers download the file instead.

### New maps and the file check

The game finds its maps through the map list in `public/assets/manifest.json` and its buildings through `public/data/buildings.json`, not by looking in the folders. The editor keeps them in step for you (Boss, 30 Oct 2026):

- **New map…** (next to the map list) starts a new area map from the open one. It copies the ground, collision, props and spawns and leaves out the buildings, doors, people and triggers, because each of those can only be on one map. It saves the map and adds it to the map list.
- **The file check** runs when you open the game, and again from **Check files**. It lists every difference, each ticked, to apply or leave:
  - a map file in `public/assets/maps` that isn't on the list, such as one copied in by hand, is added. Its id is set to match its file name if the two differ.
  - if a copied map's buildings lead into interiors another map already uses, which would stop the game starting, it offers to clear them out the way New map does.
  - a map on the list whose file has gone is taken off the list.
  - a name or kind that differs between a map's file and the list is updated.
  - a building picture in `public/assets/custom/buildings` that no building uses is added to the library as an unfinished building, and a building whose picture is missing can be marked unfinished.

New tiles need nothing: the palette is read from the folders.

Every area map also has a place on the world map (`worldMap.zones` in `public/data/world.json`). New map asks which zone the new map is in, and the file check asks for any area map that isn't in one, offering the existing zones or a new zone of its own (at the middle of the world map, with no picture of its own until one is drawn). A new map still needs a way in: an **Exit** on another map, *To* its id.

### Map tab

Paints tiles on every ground layer, edits collision, moves, copies, clears and swaps regions (buildings move with their doors), places and moves props, and checks that doors, spawns and exits sit on free tiles. An unchanged map saves back byte for byte.

**Markers** (left) adds the Data layer's objects to a game map: pick one, then click the map (drag over the tiles for an area one). The panel on the right then sets it up, with suggestions from the game's data:

- **Spawn**: where the player arrives. The first is the default; an exit or door can name another.
- **Exit**: on an area map, *To map* (or `world_map` for a road with a choice of places) and *Arrive at spawn*; in an interior, *Leaves interior*. Can be locked until a flag is set.
- **Door**: into an interior. A library building brings its own; this is for a doorway drawn with tiles.
- **Block zone**: tiles kept blocked until a story flag is set (*Lifted by flag*), then opened, with the barriers and cones on and around it cleared and the *Cleared tile* drawn over the dug-up ground (like the roadworks). Its tiles are blocked when you add it, and freed if you delete it.
- **Gate**, **Travel** (bus stop), **Venue**, **NPC** and **Interact** (with its *Action*, which the story and shops look for).

Click a marker with **Objects** (V) to change it, drag it to move it, **Delete marker** or Del to delete it. A building's own doors and returns go with the building.

### Tiles tab

A pixel editor for the map's tiles. Pick any tile on the left to edit it, start a **New tile** (1×1 for ground, taller for props), or **Import PNG…**. Tools: Pencil (P), Eraser (E), Fill (F), Picker (I or Alt+click), Line (L), Box (R, Shift fills), with pen sizes (2 matches the art's 2×2 pixel blocks), flips, a quarter turn, the game's palette and the colours already in the picture. **Seams** slides the tile half way round so the edges that meet when it sits beside itself are in the middle, where you can fix them; the preview shows it tiled 3×3.

**Save tile** writes it to `public/assets/custom/tiles/<folder>/<name>.png` and puts it in the map palette (in that folder's group); **Paint with it** goes back to the map with it on the brush. The game's own tiles (`art/`) are left alone, since `npm run import-art` copies them afresh: editing one saves your version as a new tile. Tiles in `custom/` are yours and survive an import.

### Buildings tab

The building library (`public/data/buildings.json`): pick a building or **New**, then set its name, footprint (Solid, Walkable, None), doors and returns, interior, and pictures. **Draw a new picture** opens a blank picture the size of the footprint in the same pixel editor, **Import PNG…** uses one drawn elsewhere, and **✎ Edit** changes an existing picture: the building's own pictures are saved over (maps showing it change too), and a picture cut from a shared sheet is saved as a new one of its own. Pictures go in `public/assets/custom/buildings/`. **Save to library** keeps it; tick *Unfinished* to save a draft that can't be placed yet. Back on the Map tab, **Place** puts it on the map with its doors and solid tiles.

`npm run import-art` rebuilds every game map from the Tiled sources, so edits made only to a game map are lost the next time the art is imported (tiles and building pictures in `custom/` are kept). For changes that should last, edit the `.tmj` map, then run the import. After saving, run `npm test`.

## Editing race tracks

`tools/track-editor.html` edits the race tracks in `public/data/tracks.json`, from the racing line to the ground and scenery round it. It is one file with no build step: open it in Chrome or Edge, click **Open folder…** and pick the repo, `public` or `public/data`. You edit in the game's own race camera and 3D scene, the **race view** (below). The race view runs the game in a frame: opened straight from disk, that is the published game (`https://bigdaddy284.github.io/Motocross-RPG/`, so you need to be online); with `npm run dev` running, open `http://localhost:5173/tools/track-editor.html` instead and it runs your local game (and can load the tracks from the dev server; saving then downloads the file). The editor is also published at `…/Motocross-RPG/tools/track-editor.html`. With no game reachable, it shows a plain 2D map, with a note saying why.

The editor has five modes (keys 1 to 5):

- **Layout:** the route is the shape the race screen shows: control points on the 100 × 60 grid, joined in order and back to the first point, where the finish line goes. New tracks are drawn point by point (**Draw route**; click the first point to close the route, **Close the route** and **Open the route** / **− Segment** join and take apart the loop), the drawing the game races is generated from the route, and between the features it rides as plain track whatever its shape. Each point placed shows at once (ringed, with a dashed preview to the pointer in both views) and is its own undo step; points can be dragged while drawing, a plain click on the first point closes the route and on the last stops. Drag points, double-click the route to add one, right-click or Del to remove one (the route joins up across it), and **Round corner** gives a point curve handles to drag (Alt moves one side only; **Sharp corner** takes them off). **Finish here**, **Reverse** and **Fit to grid** as before. The Route box shows the track's state: Draft, Draft with warnings, Ready for validation or Race-ready; drafts save at any time and the game leaves them out until **Ready to race** passes the checks.
- **Start straight:** the blue points. The first is the start gate (drawn as a black bar with the yellow line-up behind it), and the white one is where the straight joins the lap; it stays on the lap when dragged. **+ Start straight** (or **Start straight** in Build the lap) places one like a feature, snapping onto the lap anywhere, just before or after the finish line included; none is ever laid for you. It must be at least 12 grid units long, clear of the lap until it joins, and meet it at 75° or less. **The first corner** is its end: the stretch between its last two blue points (drawn blue and labelled First corner on the map), timed as its own stretch of lap 1 and ridden with the first corner's own rules (difficulty, skills, lap 1's first-corner incident). It is not a section: there is none to place or pick, and a First corner section on an older track rides as a flat corner.
- **Finish line:** the lap's first point, placed by you with **+ Finish line** (or **Finish line** under Start and finish, once the route is closed) or **Finish here** on a selected point, and taken off with **Remove finish line**. Placing it splits and turns the sections round so the lap is laid out as before. A track without one is a valid draft the game leaves out; the checks list it as still needed to race. A **tabletop** or **double** can be the finish line instead: tick **Finish line** in its panel and the lap starts and ends at its foot, with the finish arch built over it on the take-off lip of its front hump, its posts on the banks beside the track and its banner high enough that a rider still in the air goes under it. A scenery finish arch is not needed then (ticking the box takes one away), and moving the finish line elsewhere makes it a plain jump again.
- **Features:** every section type but the start and the plain track the route is itself (corners, hairpins, berms, ruts, jumps, whoops, sand and the rest) is a feature placed on top of the route, and only where you put it: pick one in the Features palette, it follows the pointer along the route (`,` and `.` shorten and lengthen it), a click places it; drag it along the route, drag its white diamonds to stretch it, Del removes it, and its metres, place, line and jump height are under Sections. A feature rides as its type whatever shape it is drawn (a hairpin at 90° or wide open), and moving or reshaping it, or the route under it, never changes its type. Two that overlap are allowed with a warning that names them (click it to select the feature); one past the end of the route stays in a saved draft with a warning. The sections the game races are the route's plain track cut by the features; nothing is typed from the route's shape, so a route with no features is one plain section. Tracks saved before features (`features` missing in tracks.json) keep their sections exactly as saved, with the old section list, until **Use features** (or placing a feature) keeps their corners, jumps and special sections as features at their place, with their types (a `first_corner` section becomes the start straight's end), and lets the route between them ride as plain track; nothing is reinterpreted on its own.
- **Surface:** mud, sand, water and other patches along the lap, laid by clicking the track. The stretch a click would surface follows the pointer in the surface's colour, on the map and in the race view; click a patch to select it and drag it along the lap.
- **Ground:** paint the ground tiles round the track (grass, dirt, gravel, concrete, arena floor and so on) with a brush, Shift-drag for a rectangle, or **Fill under track**. Under the plain grounds the palette has the area map's corner sets, which join grass to mud, gravel, concrete or long grass (corners, edges, inner corners and diagonals, each named for where the second ground is in the cell), and **Mixed ground**: one ground showing through another in patches (a little, patchy in two patterns, or mostly) for grass and mud, grass and gravel, gravel and mud, long grass and mud, concrete and mud, and concrete and grass, plus grass with tyre ruts each way. Each mixed tile joins up with itself, so a run of one looks like one patch of ground. They are drawn by `tools/art/ground-mix.py` from the area map's own fill tiles in the reference palette, and a ground's `group` in `trackParts.json` heads it in the palette.
- **Height:** raise and lower the track along its length. **Raise the track** (the default) and **Lower the track** work on a stretch of the route: pick a length (6 to 48 grid units, shown in metres) and a height (0.5 to 5 m), hover the track and the stretch the tool would change is highlighted on the map and as a green band on the race view in every mode of the view (the same band as placing a section, with a ring at its centre), centred under the pointer and following the route round corners and over the finish line; a click raises it (right-click lowers it) by the height at the centre, easing with a smooth cosine curve to the track's own level at both ends, so there is no kink. Each click is one undo, nothing changes until you click, and a second click on the same stretch steps the same hill up or down instead of piling another on it. The track keeps its width, banking, berms and section types; the ground either side rises or sinks to meet it as a grass slope no steeper than 1 in 1.5, with the usual earth lip and bank along the edge, and riders slow up climbs and run quicker down drops. A click that would take the track past ±36 m is refused with a message, and a stretch made steeper than 35% is warned about in the status line and Checks. The hills are saved with the track as `"hills": [{"at": <grid units round the route>, "len": <grid units>, "height": <metres>}, …]`, follow the route when points are inserted, deleted, reversed or fitted to the grid, and are copied by Duplicate. The older ground brushes (**Raise ground**, **Lower ground**, **Smooth**, **Flatten**, with a radius and a strength) are still there for shaping the land around the track; they paint the ground lattice, the map shows raised ground warm and lowered ground blue with a contour every metre, and the track follows the ground under its middle as before. **Flatten all** removes the hills and the painted ground.
- **Scenery:** banners and sponsor boards with your own text, tuff blocks, hay bales, tyre walls, tape, start gates, grandstands, crowds, floodlights, pit tents, vans, trees and more. Drag to move (the arrow keys nudge), Q and E to rotate, Shift-click or Shift-drag a box to select several (Ctrl+A all) and move, turn, copy or delete them together, Ctrl+C, Ctrl+X and Ctrl+V to copy, cut and paste at the pointer, Ctrl+D to copy (with Snap object on, the copy stands end to end with the item, so pressing again runs a fence on), Del to remove. Two snaps in the toolbar: **Snap grid** lands items on half grid units, and **Snap object** joins an item placed or dragged near another onto it, end to end or side by side with their edges flush and turned the same way when it is already within 12° of lining up (turned further by hand it keeps its own angle, and only its position snaps), so a run of fences or walls lines up (the item it joins gets a dashed outline). While an item is snapped, and once it is placed with an end joined onto another, Q and E swing it round the join instead of its middle, so a fence can turn off in another direction and stay joined (with both ends joined it keeps the end on the item placed first). Hold Alt to drop both for one move. A white arrow on the item being placed or selected, on the map and in the race view, shows which way it faces (people, stands, boards and tents face it, vehicles point their nose along it, and a marshal, flag man, pit crew, fans or TV crew not turned by hand face the track). Scenery may stand up to 20 grid units outside the build boundary. **Cheering fans** (`cheer`) have a variant (body shape), an action (arms up, wave, clap, fist pump, celebrate), a shirt colour and an optional route: with one, they walk in from where placed to its end when the track loads and cheer from there; without, they cheer where placed. Each fan reacts in their own time to a bike passing within 7 grid units, with a rest between. A fan on the track, where placed or where the walk ends, fails the checks. Pick an item and it follows the pointer see-through on the map and in the race view, where a click would place it, turned as Q and E have turned it (the turn is kept for the next item). Q and E turn an item 15° a press, 5° with Shift and 1° with Ctrl (Alt+E would open the browser's own menu), and the Turn box takes any whole number of degrees. **Paddock vehicles** (`rusty_truck`, `rusty_van`, `mx_van`, `mx_van_long`, `motorhome`, `motorhome_long`, `hauler`, `bike_stand`) are the game's seven van designs (`public/data/vehicles.json`) built for the race view at the race bikes' scale, from their real sizes (a 4.9 m pickup to the 21 m factory hauler; the bike's 1.46 m wheelbase is `BIKE_LENGTH` grid units): an old rusty truck with nothing, one or two bikes on the back; an old rusty van with its doors shut or open and a bike beside it; the MX vans and sports motorhomes closed up, with the awning out, or with bikes on stands under it; the factory hauler closed or with a three-sided awning the length of the trailer and five bikes under it; and a bike on a stand (adult or youth). Each definition in `trackParts.json` lists its `setups` (the item's `action`), `variants` and `colours`; an item that names none gets them picked for it from its place in the list, the same each time, like a fan's shirt, and the panel shows what was picked with the swatches and set-ups to choose instead. The body stands at the back of the footprint and alone counts as solid; the awning side (the lower side on the map before turning) and the bikes under it are not. `src/core/paddock.ts` picks the options and `src/world/paddock.ts` builds the vehicles as one mesh each. **Trackside items** (`src/world/trackside.ts`, mirrored by the editor's `TRACKSIDE` table) are forty more built the same way, in metres at the race bikes' scale, each with a colour and, where it has them, a design (`variant`) and a set-up (`action`) picked for it unless chosen, and a `text` where it has words: the TV crew and media (`tv_camera_op`, `tv_tripod`, `tv_van`, `tv_tower`, `camera_crane`, `drone_pilot`, `photographer`, `commentary_box`, `big_screen`, `press_tent`), the pits (`pit_setup` with bikes, people, both or tools and the team's name on the valance, `bike_wash`, `bike_trailer`, `pit_clutter`, `trade_stand`, `merch_trailer`, `catering_van`, `marquee`, `time_check`, `signing_table`), over and beside the track (`foot_bridge`, `timing_beam` and the `inflatable` arch stand over the track like a finish arch, solid at their ends only; `crowd_barrier`, `cones`, `marshal`, `ambulance`, `quad`, `tractor`, `skid_steer`, `toilets`, `feather_flags`, `pa_speaker`, `vip_stand`) and the fans (`camp_chairs`, `fan_photo`, `lunch_table`, `picnic`, `fan_parasol`, `fans_fence`). The bridge, barrier, cones, fence, timing beam and VIP stand run as far as their width, like a banner. People face the track in the race view unless the item is turned by hand; every item is one vertex-coloured mesh plus a textured box for each label. The **bike on a stand** offers six bike models (`src/world/raceBike.ts` `MODELS`): the adult and youth MX bikes races ride, and four for scenery only, the 50cc mini, the pit bike, the enduro bike with lights and the vintage twin-shock; races still pick the youth or adult model from the class, whatever stands round the track. **Marshals** (`marshal`, `src/core/marshal.ts`) watch the track: each keeps the yellow flag down until a rider is down (crashed, or getting back on) on their watch, then leans out and waves it until the rider is away, in the race and the editor's race view alike. The watch runs in the lap direction from the nearest point of the track to the marshal to the end set with the panel's Set watch (click the track; the marshal's single `route` point), capped at 36 grid units (about 48 m, the editor warns past it), or the next 18 units of track with no end set; the editor draws it as a yellow band and the marshal faces its middle unless turned. Five designs: standing trackside, on a pallet stand, in a roofed tower (both with the platform a metre up, at handrail height), a pair with an extinguisher, and behind hay bales; four vest colours. **Supercross kit** (Boss, 28 Oct 2026): a `podium` (motocross: three numbered boxes and a sponsor board; supercross: a lit stage with steps and a backdrop; empty, with the top three, or spraying champagne, with your sponsor's name), a `holeshot_board`, `pyro` flame pods along their width (ready or firing), a `truss_arch` lighting truss over the track with its lights and an optional banner, a `stadium_tunnel` (the riders' way onto the floor through a stadium wall with the seating behind) and a `trophy_table`. **The finish line crew** (Boss, 29 Oct 2026; `src/core/finishCrew.ts`): the **flag man** (`flagger`) stands on any of the marshals' five stands, just before the finish line. As the leader comes up to him (within 24 grid units) to start the last lap he holds up the white flag in his left hand; as the leader comes up to finish he lowers it and only then raises the chequered flag in his right, waving it until every rider still racing has passed him, then lowers it. **Pit crew** (`pit_crew`: standing, behind a pit wall, or with a mechanic; team shirt colours) stand just after the line. In a race each is given a CPU rider (the same picks each race on a track, different riders while there are enough), and as that rider comes up to them each lap they lean out holding the pit board on its pole, showing the rider's place and the laps to go (LAST on the last lap), until the rider is 3 grid units past. The player's own pit crew comes later, with the fourth pit board message. Both face the track unless turned, and Checks warns when one stands more than 12 grid units round the lap from the finish line or the track has no finish line. In practice and in the editor they stand ready.
- **Build boundary:** the dashed translucent rectangle is the 100 × 60 race ground. A stretch of the route may cross it by up to 12 grid units while the track is shaped, with a warning that names the points either side and where it leaves; the track is not ready to race until it is back inside, and a saved draft keeps the crossing. Scenery may stand up to 20 units outside.
- **Track details:** id, name, kind (stadium, outdoor or endurance), track width, size, surface, practice only, and the start gate curve. Renaming an id updates the venues that use it.
- **Supercross sections** (`racing.json`, `src/core/jumps.ts`, `src/core/trackSurface.ts`, `src/core/riderAI.ts`), from the supercross jump chart: **Tabletop**, **Double**, **Triple**, **Quad**, **Step-up**, **Step-down**, **Step-on step-off** (a single, a gap, a tabletop with a slight lip on its end, and a single: hopped on, then off the lip; **Step-on, two tables** and **Step-on, three tables** put more tabletops between the singles, hopped lip to table), **On-off** (a deck hopped onto, then a double off it), **Single over table**, **Table over single**, **Wall jump** (a steep face with a sheer back), **Ski jump** (a long ramp flown off into a long sloping landing), **Rhythm section**, **Rollers** (long low rolls, ridden) and **Dragon's back** (four humps each bigger than the last, building up to a big final mound that is launched off). Every jump is a row of humps and a list of ways to take it as hops from a take-off to a landing (`jumps.ts`): a tabletop is cleared or landed short of the end and ridden off, a double cleared or singled, a triple tripled or doubled then singled, a quad taken as a quad, a double-double, a single-double-single or a triple-single, a dragon's back skipped top to top or doubled, and so on. Each rider picks a way for each jump on each lap by their jumping (the jumps and ruts skill, the bike's power and the race message's risk), the same for the same race, and a mistake on a jump is the way that comes up short, landing on the face. The race view flies each wheel along the hop it is in, launched along the face it rode up (scrubbed flatter by a scrubbing rider) and always clearing what is between, so a bike leaves the lip front wheel first and lands where the hop says.
- **Tunnels:** a tabletop, step-up or step-on feature has a **Tunnel** choice (saved as `tunnel` on the section): *The track passes under it* when another part of the lap is drawn across its deck (the flat top in the middle), so riders there ride through the tunnel while the rest jump over it, or *A pedestrian tunnel*. Both sides of the deck become concrete walls with the opening and a portal frame; the map draws the hole as a dark band. Choosing the track tunnel lengthens the feature to 22 grid units and raises it to 3.5 m where it is less, and the checks say when nothing passes under the deck, when the deck is too short for the lower track (longer where it crosses at a slant), or when the jump is too low. A crossing with no tunnel is still only a warning, as before; the race simulation is unchanged, the lower track riding at ground level under the deck.
- **Finish arch:** the `finish_arch` item always spans the track's width (its posts just outside the lips, `src/core/trackClearance.ts` `archSpan`), whatever width it was saved with, and belongs on the finish line, square to the track: placing the finish line moves every arch there, the arch's panel has **Put on the finish line**, and the checks warn when one is off it.
- **Checks** run the game's own rules for `tracks.json` and `trackParts.json`, the section shapes and the start straight included, grouped as Circuit, Race start, Finish line, Height and Geometry (with a ✓ line for each part in place), and warn about race tracks without a gate curve, drawings that cross themselves with no tunnel, and corners so tight the racing surface folds (the section is named and marked amber in the sections list; click the warning to find it). They run on load, on every change, on Save (the status line gives the count) and with the **Check** button. Scenery is checked by what of it stands at riding height, turned as placed (a tree's trunk, a floodlight's pole, a banner's thin line, a finish arch's two posts): on the racing surface is an **error** (outlined red), within half a bike's width of its edge or two solid items inside each other is a **warning** (dashed yellow). Click a scenery check to select that item. Ground steeper than 45° (a wall) or past 36 m up or down is an error; a track climbing or dropping more than 35% along its length is a warning. Checks never change the track.
- **Race view:** the editor's view is the game's race screen 3D scene and camera, showing the open track as a race draws it: hills, jumps, banking, ground tiles and scenery, with the lap map in its top-right corner. Every mode's tools work in it: click, drag and right-click on the 3D ground and the tool acts on that grid point, with the keys 1 to 5, Q, E, Del, Ctrl+Z, Ctrl+S and so on. Camera: mouse wheel or + and − zoom, W A S D or a middle-button drag (or Space and drag) pans, [ and ] turn the view 45° at a time, 0 resets it. The selection is orange, errors red, warnings dashed yellow, the brush white. In Layout the lap's points show as white rings and the start straight's as blue squares. Each section shows as a stripe down the middle of the track in its kind's colour (the Section colours legend), and a cream line edged dark crosses the track where one section ends and the next begins (the finish line has its own). The lines come from the section lengths, follow the bends, redraw on every edit and stay a readable width at any zoom. No race, riders or race AI run in the view, and the game itself never shows these markers. The view draws only when something changes, so a still view costs almost nothing.
- **Preview** rides a dot round the lap in the race view. **Race it in the game** opens a race day on the track in the game (`/?testtrack=<id>`, with `npm run dev` running and the track saved); with unsaved changes it asks first, because the game races the saved file.
- **Export / Import** save one track as a `.track.json` file and add one back, a first step towards player-made tracks.
- **Undo / Redo** with Ctrl+Z and Ctrl+Y.

The lists of track kinds, surfaces, ground tiles and scenery are in `public/data/trackParts.json`, with tile art from `public/assets/art/area-map/tiled/tiles`. Its `sectionEditor` switch shows the section editing tools while the game is in development; Final v1 turns it off (preview with `?final=1`), leaving the layout, surface, ground and scenery editing. The section data and the race simulation work the same either way.

A new track can be raced from the world once a venue in the `venues` list of `tracks.json` points at it. An unchanged file saves back byte for byte. After saving, run `npm test`.

## Models

The **Models** card (or **Models…** in the track editor, or the game with `?models`) lists the race view's objects: the race bike (adult and youth), the race rider and every scenery item that can be swapped. Pick one to see it turning on a 1 m grid with its size and triangle count, then click **Export** to save it as a `.glb` that Blender opens. Change it in Blender, export it as glTF Binary into `public/mods/models/` under the same name to replace it, or under a new name to add a new scenery item, and reload. The page's last list, **Your models**, shows every file in that folder with what it does in the game, or in red why it isn't used. The rules for each type are in [MODELS.md](MODELS.md).
